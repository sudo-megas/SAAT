# SAAT v2.1.1

A small patch release: three robustness fixes, no new features, and your
collection is untouched. Install it over v2.1 and your watches, photographs and
settings stay exactly where they are.

## Now actually run on Windows

v2.1 shipped with an honest caveat — the automated tests passed on Windows in CI,
but nobody had run the installer on a real Windows machine. Someone now has, on
Windows 11, end to end: the installer completing with no administrator prompt,
the Start Menu and desktop shortcuts, the bundled Ubuntu fonts, the tray icon and
close-to-tray, the collection landing in `%LOCALAPPDATA%\SAAT`, and uninstalling
with the collection left intact. **All six of those held.**

These three fixes are the smaller things found alongside that run.

## Fixed

### Photos with awkward filenames

Watch *folder* names were already checked against names Windows cannot create
(`con`, `nul`, `lpt1`, …). Imported *image* filenames were not — a photo whose own
name was one of those, or was very long, or held characters Windows forbids, could
be written under a name Explorer could not open, or fail to import at all.

Image filenames now get the same treatment folders do: reserved names are made
safe, forbidden characters are removed, over-long names are shortened — while the
extension and the recognisable part of the name are kept. The photo you dropped in
as `nul.jpg` is stored as `nul-image.jpg` and behaves like any other.

This applies on every platform, because a collection is a folder of files that
gets copied between machines, and a name one machine accepts and another cannot
open is a name that breaks the moment the collection travels.

### A byte-order mark no longer wipes your settings

`config.toml` holds your window size, palette, language and column choices. If you
opened it in a Windows editor that adds a UTF-8 byte-order mark — Notepad does,
among others — and saved, the next launch treated the file as corrupt and quietly
reset everything to defaults. It is now read correctly. A genuinely broken config
still falls back to defaults, as before.

## Changed

### Upgrading while SAAT is open

Because only one copy of SAAT runs against a collection at a time, upgrading while
the app was open could fail on a locked `SAAT.exe`. The installer now closes a
running SAAT before upgrading — Windows' own Restart Manager does this — and does
not relaunch it afterwards. Nothing about the "uninstalling never deletes your
collection" guarantee changes.

## Everything else is unchanged

No features were added or removed, no data format changed, and Linux behaves
exactly as it did in v2.1 — the `.deb` and the tarball are built the same way, and
still never touch your collection when removed.
