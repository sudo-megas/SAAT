# SAAT v2.0

SAAT is now a Debian package. On Debian, Ubuntu, Mint and their derivatives you can
install it with `apt` and it appears in your application menu — no extracting a folder,
no deciding where to put it, no `install.sh`.

Nothing about the app itself changed in this release. This is entirely about how you get
it and how you remove it.

## Install on Debian, Ubuntu or Mint

Download `saat_2.0-1_amd64.deb` from this release, then:

```sh
sudo apt install ./saat_2.0-1_amd64.deb
```

That is the whole procedure. SAAT appears in your application menu with its icon, and
`saat` works from a terminal. There is also a manual page now: `man saat`.

Your collection lives in `~/.local/share/saat` and your settings in `~/.config/saat`,
which is the standard place for both — the package does not keep your data in with the
program.

It needs glibc 2.35 or newer, so: Debian 12 and newer, Ubuntu 22.04 and newer, Mint 21
and newer.

The package is about 230 MB installed, and that deserves an honest explanation rather
than a surprise. It carries its own copy of Qt and Python instead of using your
distribution's, which is almost all of that size. The benefit is that it behaves
identically to the portable version and does not change behaviour when your distribution
updates its Qt packages — it is the same build, tested once, rather than a second one
assembled against whatever each distribution happens to ship.

## Removing it never deletes your collection

```sh
sudo apt remove saat
sudo apt purge saat
```

**Both leave `~/.local/share/saat` and `~/.config/saat` completely untouched.** Every
watch you have entered, every photograph, every day of wear history stays exactly where
it is, including after `purge`.

This is not a promise made in good faith and hoped for. Every release build installs the
package, writes a file into a collection directory, purges the package, and then checks
that the file is still there and unchanged — and refuses to publish the release if it is
not.

If you later reinstall SAAT, your collection is simply there again.

## Other distributions: nothing has changed

The portable `.tar.gz` is still here, still built the same way, and still works exactly
as it did:

```sh
tar -xzf SAAT-v2.0-linux-x86_64.tar.gz
cd SAAT
./SAAT
```

It remains the right choice on Fedora, Arch, openSUSE, or anywhere without `apt`, and
the right choice if you want SAAT on a USB stick. In this mode your data lives **beside
the executable** rather than in your home directory, so moving the folder moves the
collection with it. That behaviour is unchanged and deliberately so.

Both downloads come from the same build. The `.deb` is that same folder, wrapped — not a
separately compiled version that could behave differently.

There is also still `install.sh` in the repository for a system-wide install without a
package manager.

## Which one should I use

If you are on Debian, Ubuntu or Mint and this is your own computer, use the `.deb`. It
puts SAAT in your application menu and keeps your collection in the standard location.

Use the tarball if you are on another distribution, if you want to carry the collection
between machines, or if you would rather not install anything system-wide.

## Also in this release

- `man saat` documents where your data lives in each mode, and the `SAAT_DATA_DIR`
  override.
- The README is now written for people installing SAAT rather than people building it.
  Build instructions moved to `docs/BUILDING.md`.
- The package declares its licensing in full: SAAT is GPL-3.0-or-later, and every
  library bundled inside it — Qt, Python, and the rest — is accounted for in
  `/usr/share/doc/saat/copyright`, alongside a manifest of exactly what the package
  contains.
