# SAAT v2.1

SAAT runs on Windows.

There is an installer for Windows 10 and 11, and a portable `.zip` if you would
rather not install anything. Linux is unchanged — the tarball and the `.deb` are
still here and still work exactly as they did in v2.0.

## Windows

Download `SAAT-v2.1-windows-x64-setup.exe` and run it.

### Windows will warn you, and you have to click past it

The installer is not code signed, so Windows SmartScreen shows a blue box saying
**"Windows protected your PC"** with only a **Don't run** button visible. To
continue:

1. Click **More info**
2. Click **Run anyway**

That is two clicks and there is no way to avoid them. The warning means "this
publisher has not paid for a certificate", not "this file is known to be harmful" —
SmartScreen shows it for every unsigned installer from a publisher it has not seen
before. A code-signing certificate costs a few hundred dollars a year, this is a
free hobby project, and buying one has not been decided either way.

If that trade is not acceptable to you, that is a reasonable position: the project
is source-available and you can build it yourself, or use the portable `.zip`, which
trips SmartScreen less often because there is no installer to run.

### What the installer does

- Installs **just for you**, to `%LOCALAPPDATA%\Programs\SAAT`. It never asks for
  administrator rights and never shows a UAC prompt.
- Adds a **Start Menu** entry. A desktop shortcut is offered as a tickbox, off by
  default.
- Registers a normal uninstaller, so SAAT appears in **Settings → Apps** and is
  removed the same way as anything else.

Your collection lives in `%LOCALAPPDATA%\SAAT` and your settings in `%APPDATA%\SAAT`
— the standard Windows locations, and deliberately *beside* the program directory
rather than inside it.

**Uninstalling never deletes your collection.** Every watch, every photograph, every
day of wear history stays where it is. The uninstaller removes what it installed,
and your data is not somewhere it can reach.

### The portable zip

Extract `SAAT-v2.1-windows-x64.zip` anywhere and run `SAAT.exe`. In this mode SAAT
keeps `watches\`, `config.toml` and `backups\` **inside the extracted folder**, so
you can put the whole thing on a USB stick and carry the collection with it.

### What has and has not been tested on Windows

Worth being straight about. Every automated test now runs on Windows in CI, and the
Windows build is produced and launch-tested there on every release. That is a real
gate and it is more than most hobby projects do.

It is also not the same thing as somebody using it. **Nobody has yet run the
installer on a real Windows machine, clicked the Start Menu shortcut, or looked at
the app on a Windows screen.** If something is visually wrong, if the tray behaves
oddly, or if the installer misbehaves in a way a test cannot see, that is entirely
possible and worth reporting.

Your collection is safe either way — it is plain TOML files in a folder you own, and
nothing in this release changes how they are written.

## Linux: nothing has changed

The `.deb` and the portable `.tar.gz` are built exactly as they were in v2.0:

```sh
sudo apt install ./saat_2.1-1_amd64.deb
```

Removing or purging the package still never deletes `~/.local/share/saat` or
`~/.config/saat`, and that is still checked automatically on every release build.

## Improvements that apply everywhere

Three fixes came out of making the app work on Windows, and all three apply on Linux
too, because a collection is a folder of files that gets copied between machines:

- **Two watches whose folder names differ only by capitalisation are now treated as
  the same watch.** On Linux they were two folders; on Windows they are one. Without
  this, a collection made on Linux could quietly lose a watch when opened on
  Windows.
- **Watch folder names are checked against names Windows cannot create.** A handful
  of ordinary-looking words (`con`, `aux`, `nul`, `com1`…) are reserved on Windows
  and would have produced a folder that could not be written.
- **Saving now retries briefly if a file is momentarily locked**, which on Windows
  antivirus and search indexing routinely cause. It also no longer leaves a stray
  `watch.toml.tmp` behind if a save fails — that was a small Linux bug nobody had
  noticed.
